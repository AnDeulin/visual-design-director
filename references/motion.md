# Движение и современные приемы

Выбери цель движения и самое простое достаточное средство. Учитывай стек и целевые браузеры. Примеры — отправные точки, не обязательный набор эффектов.

| Задача | Подход | Проверка |
| --- | --- | --- |
| Обратная связь и локальная смена состояния | CSS transitions, преимущественно transform/opacity, если они соответствуют смыслу | Кнопка/действие реагируют сразу; эффекты не скрывают и не блокируют важные элементы |
| Вход/выход, общая геометрия React-компонентов | Motion, если уже подходит стеку | Правильные состояния и прерывание; [официальная доступность](https://motion.dev/docs/react-accessibility) |
| Смена вида/страницы с сохранением ориентации | [View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API) | Рабочая навигация без эффекта, поддержка браузеров, спокойный вариант |
| Объяснение прогресса при прокрутке | Scroll-driven motion; [руководство Chrome](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/motion) | Контент доступен без движения/JS; нет захвата прокрутки и лишней нагрузки |
| Разный размер одного виджета | [Container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries) | Проверка в узком и широком контейнере, а не только на двух viewport |
| Переход между этапами объяснения в HTML-слайдах | [reveal.js Auto-Animate](https://revealjs.com/auto-animate/) | Сопоставление элементов, порядок чтения и понятный статический экспорт |

Маска, clip-path, зерно, градиент, 3D, параллакс и кинетическая типографика могут дать выразительный акцент. Выбирай эффект из содержания и бюджета производительности. Например, редакционный лендинг может выдержать крупное раскрытие текста, а рабочему дашборду полезнее спокойное обновление фильтра и сохранение положения пользователя.

## Reduced motion

[`prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) — предпочтение пользователя. Для reduce убирай или заменяй несущественное перемещение/параллакс, сохраняя смысл и обратную связь. Проверяй CSS, JS, smooth scroll, canvas и фоновое видео отдельно.

`MotionConfig reducedMotion="user"` отключает transform/layout-анимации, но может сохранять opacity/backgroundColor. При необходимости используй [`useReducedMotion`](https://motion.dev/docs/react-use-reduced-motion) для осознанной замены. Не считай одну настройку полным покрытием всех движений страницы.

Не применяй глобальное `animation: none` без проверки: приложение может зависеть от animationend. Нужны явные состояния, работающие независимо от эффекта. Автоматически движущемуся содержимому предоставляй подходящее управление; эффект не должен требовать точного наведения или преследования объекта.

## Проверка

Посмотри реальный результат при обычном и уменьшенном движении. Проверь клавиатуру/касание, возможность прервать переход, поведение при повторном действии и отсутствие скачков/перекрытий. Проверяй поддержку по актуальной документации, а производительность — в целевой среде, если она существенна. Снижать качество текста/изображений ради декоративной анимации обычно невыгодно.

Для осмысленной хореографии полезны первичные авторские разборы: [Josh Comeau: CSS transitions](https://www.joshwcomeau.com/animation/css-transitions/) и [Val Head: reduced motion](https://www.smashingmagazine.com/2020/09/design-reduced-motion-sensitivities/). Они помогают выбирать прием; API сверяй с текущей документацией.
