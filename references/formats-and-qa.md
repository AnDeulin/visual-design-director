# Форматы и проверка

Читай нужную ветку. Существующий шаблон, точный формат и требования пользователя имеют приоритет перед стилем навыка.

## Сайт

Сначала сценарий, структура и ключевое действие, затем внешний вид. Реализуй навигацию, взаимодействия и необходимые состояния. Свяжи композицию первого экрана с остальным содержанием. Проверяй реальные русские тексты, узкий/широкий экран, масштабирование, клавиатуру, фокус, hover/touch, ошибки и пустые состояния. Не добавляй фиктивные отзывы/статистику как реальные факты.

Сохраняй семантику и разумный порядок чтения при выразительной композиции. Для медиа укажи размеры, проверяй загрузку и адаптивные варианты. Новые зависимости должны решать реальную задачу. Если сайт создается через доступный Sites workflow, соблюдай его правила реализации, проверки и размещения; этот навык сам по себе не разрешает публикацию.

## Дашборд

Начни с решения пользователя: что он должен понять и сделать. Показывай нужный период, единицы, источник, обновление и базу сравнения KPI. Различай ноль, missing, loading и error. Демо-данные помечай как демонстрационные.

Выбирай график по задаче: сравнение категорий — обычно bars/dots; динамика — линии; распределение — histogram/box и подходящие альтернативы; связь — scatter. Для долей учитывай точность сравнения и число категорий. Не обрезай ось столбчатой диаграммы без явного обоснования; для линии выбери масштаб, который не вводит в заблуждение. Периоды и серии должны оставаться сопоставимыми.

Ставь смысловой заголовок, подписывай единицы/оси, используй прямые подписи там, где они упрощают чтение. Цвет не должен быть единственным носителем смысла. Tooltip дополняет, а не заменяет подписи и доступ к значениям. При необходимости дай таблицу и текстовое объяснение тренда.

Проверь реальные фильтры, сортировку, выбранный диапазон, empty/loading/error, длинные названия, большие/отрицательные значения, клавиатуру и экспорт. Следи за стабильной геометрией при обновлении данных и понятной плотностью.

Первичные источники: [Carbon: chart anatomy](https://www.carbondesignsystem.com/building-blocks/data-visualization/chart-anatomy), [Observable Plot: accessibility](https://observablehq.github.io/plot/features/accessibility), [W3C: complex images](https://www.w3.org/WAI/tutorials/images/complex/). ARIA на SVG не доказывает доступность всего интерактивного дашборда.

## Презентация

Определи показ: выступление, переговоры или самостоятельное чтение. Для каждого слайда сформулируй тезис и доказательство; плотность и размер текста выбирай по условиям. Используй сетку/направляющие, последовательные поля и повторяемые стили. Осмысленная асимметрия допустима; миниатюра страницы сайта редко работает как полноценный слайд.

В запрошенном PPTX сохраняй редактируемость там, где она нужна. Не заменяй PPTX HTML-деком ради удобной анимации. Для существующего шаблона используй реальные masters/layouts. Проверь открытие и экспорт, шрифты, переполнения, изображения, заметки и порядок элементов. Для PDF смысл должен сохраняться без движения.

HTML-деки могут использовать [reveal.js](https://revealjs.com/auto-animate/), но [PDF export](https://revealjs.com/pdf-export/) проверяется отдельно: разбиение по страницам, фоны, растяжение, появление элементов и число страниц. Доступная библиотека в sources не означает, что она уже установлена или предпочтительна для пользователя.

## Доступность и материальные проверки

Для веба проверяй применимые критерии, а не заявляй compliance по короткому списку:

- [Контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum): обычно 4.5:1; крупного текста — 3:1 с определением и исключениями источника. Не любой заголовок автоматически крупный.
- [Значимые UI-признаки/графика](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html): 3:1 к соседнему цвету с исключениями. Это не требование рамки вокруг каждой кнопки.
- [Размер цели AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 24×24 CSS px либо выполнение предусмотренного исключения, включая spacing. Более крупные цели могут быть удобнее, но 44×44 не универсальный AA минимум.
- [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html): для применимого вертикального контента проверка 320 CSS px; у объективно двумерных частей есть исключения. Проверь реальную функциональность и увеличение.
- Видимый фокус, клавиатура и [фокус, не скрытый полностью](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), включая sticky элементы; проверь порядок и работу интерактивных контролов.

Для слайдов/экспорта нужны свои проверки чтения, структуры, альтернатив и конечного приложения; один веб-чеклист недостаточен. Если инструмент проверки недоступен, обозначь непроверенную часть без заявления о полном соответствии.
